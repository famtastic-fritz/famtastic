# SUMMARY — Lucid

## What I built

A private, single-user **dream interpretation app**, running fully offline with
one command (`npm start`) and zero dependencies (pure Node.js stdlib).

**The three jobs from the spec, all working:**

1. **Layered capture** — type (always works), optional guided prompts
   (who/where/feeling/vividness/recurring), and a real voice-record button.
   Transcription is stubbed behind a clean `transcribe()` seam; the mic records
   and the flow degrades gracefully to typing until you add a speech key.

2. **Conversational interpretation** — a genuine *elicit → clarify → interpret*
   flow, not a one-shot box. It detects dream symbols, asks one or two gentle
   follow-ups, then composes a warm, reflective reading (emotional thread +
   what the symbols may point to + a question to sit with). The interpretation
   is generated by a self-contained offline interpreter; an `interpret()` seam
   lets you swap in a real LLM later with no UI changes.

3. **Journal + Patterns** — every dream and its reading saved locally and
   searchable; recurring symbols surfaced across all dreams
   ("You've dreamed about water 5 times").

**Vibe:** calm & nocturnal — midnight indigo, soft glow, starfield, a moon,
hushed serif interpretations. Warm and exploratory, never doom-y.

**Proof:** 13/13 tests pass; the server was booted and exercised end-to-end
over HTTP (see `PROGRESS.md`).

## Architecture at a glance

- `server.js` — zero-dep HTTP server + JSON API + tiny `.env` loader.
- `src/symbols.js` — the symbol knowledge base + detection/tagging.
- `src/interpreter.js` — clarify questions + offline interpreter + provider seam.
- `src/transcriber.js` — voice→text seam (stub until a provider is set).
- `src/store.js` — local JSON persistence (`data/dreams.json`).
- `src/patterns.js` — recurrence across dreams.
- `public/` — the calm-nocturnal single-page UI.

## Assumptions I made (logged, override anytime)

- **Name** = "Lucid" (working name; trivial to change).
- **Vibe** = calm-nocturnal + subtle mystical; **voice** = warm/reflective with
  light symbolic touches.
- **Storage** = a single local JSON file (no DB server) — simplest thing that
  fully satisfies "local, private, single-user."
- **Zero npm dependencies** — chosen so `npm start` always works with no install
  step or network.
- **Symbol knowledge is self-contained** (15 common dream symbols) rather than
  scraping an external dream dictionary — that was explicitly out of scope for v1.
- **Persistence:** committed into the feature branch (not a private nested repo)
  so it survives ephemeral cloud containers and is pullable to any machine.

## How to extend

- **Real AI interpretation:** fill in `interpretWithProvider()` in
  `src/interpreter.js` + set keys in `.env` (see `SETUP.md`). The shape it
  returns is already defined.
- **Real voice:** fill in `transcribeWithProvider()` in `src/transcriber.js`.
- **More symbols:** add entries to `SYMBOLS` in `src/symbols.js` — detection,
  tagging, and patterns pick them up automatically.
- **Richer patterns:** `src/patterns.js` already aggregates by symbol and theme;
  add time-windowing or per-person tracking there.

## Three questions that would change the next iteration

1. **Interpretation depth vs. live AI** — the offline interpreter is real and
   warm but rule-based. Do you want me to wire in a live model now (you'd add a
   key), or keep it fully offline and instead deepen the local symbol library
   and make the readings longer/more personal?

2. **Memory across dreams in the reading itself** — right now patterns live on
   their own tab. Should the *interpretation* actively reference your history
   ("you've dreamed of water before, and last time you felt…")? That turns it
   from per-dream into a continuous companion.

3. **Where does this live long-term** — pure-local single file is great for
   privacy on one machine. Do you want it to stay a local-only personal tool, or
   should the next iteration add encrypted sync / a phone-friendly installable
   (PWA) so your journal follows you to bed without a laptop?
